# Protocol 1.0

Transport is IPv4 TCP bound only to `127.0.0.1`, with an ephemeral port discovered
from `.godot/godotbridge/connection.json`. Each frame is a **4-byte unsigned
big-endian length**, followed by exactly that many UTF-8 JSON bytes. Length must
be 1–4,194,304 bytes. TCP fragmentation and coalescing are handled explicitly.

## Handshake

The first request must be authenticated:

```json
{"protocol_version":"1.0","request_id":"hello","method":"handshake","params":{"token":"SESSION_TOKEN"}}
```

The success result contains protocol_version, Godot/plugin versions, project path,
project name, main scene, and supported wire capabilities. Tokens are generated
from 32 cryptographically random bytes per plugin session and are never returned
in handshake results. Wrong tokens close the connection after an error response.

```json
{"protocol_version":"1.0","request_id":"request-123","method":"node.create","params":{"parent":".","type":"Node3D","name":"TestObject"}}
```

```json
{"protocol_version":"1.0","request_id":"request-123","ok":true,"result":{"node_path":"TestObject","class":"Node3D"}}
```

```json
{"protocol_version":"1.0","request_id":"request-123","ok":false,"error":{"code":"NODE_NOT_FOUND","message":"Node does not exist: Missing"}}
```

Request IDs are strings of at most 128 characters. Unknown versions, methods,
invalid envelopes, oversized frames and malformed JSON fail safely. Eight
connections, a 32-request queue and 30-second idle sessions bound server resources.
Only one request per connection may be pending. There is no replay/deduplication
contract: do not resend uncertain mutations automatically.

Python opens and authenticates a new connection per operation, so later calls
automatically discover a restarted editor's token/port. One deadline covers the
handshake and response. Every response ID/version is checked.

`python/godotbridge/models.py` is the operation source of truth.
`addons/godot_bridge/schemas.json` is generated by `scripts/sync_schema.py` and
validated in tests. The engine implements the JSON Schema subset those models
emit, with additional recursion, property and name checks.

Client-composed operations (snapshots, validation/import, managed runtime/logs)
are not all wire methods. `scene.snapshot` composes tree inspection and capture,
then writes the result files in Python. `viewport.capture` returns a private
temporary image path to the client; it never accepts an arbitrary output path
for the plugin to write. CLI/MCP then validate and copy the artifact within the project.

## Node mutation rules

Mutating `node.*` methods return `READ_ONLY_RESOURCE` when the editor itself would
not allow the change, with these rules:

- **@tool scripts:** nodes whose script `is_tool()` are rejected unless the request
  sets `allow_tool_script: true` (default `false`). Non-`@tool` scripted nodes are
  editable; their exported variables appear in `node.properties` with
  `"script": true` and `node.set_property` type-checks values against them.
- **Instances:** the instance root (owner is the edited root) accepts all
  operations. Nodes inside an instance accept `node.set_property`,
  `node.set_transform` and new children only when the owning instance root has
  editable children (`node.set_editable_children`); delete, rename, reparent and
  duplicate are always rejected. `node.instantiate` adds an instance
  (`scene`, `parent`, optional `name`); self or recursive instancing is
  `INVALID_ARGUMENT`.
- **Inherited scenes:** nodes of the base scene chain accept property/transform
  edits and new children but not delete, rename, reparent or duplicate.

`node.inspect` and `scene.tree` entries report `script`, `tool_script`, `groups`,
`inherited` and `instance` (`is_instance_root`, `editable_children`,
`inside_instance`).

## Typed values

No raw Variant stringification is used. Primitive bool/number/string/null values
use ordinary JSON. Unsupported values are marked explicitly in read results.

```json
{"type":"Vector2","value":[1,2]}
{"type":"Vector3","value":[1,2,3]}
{"type":"Color","value":[0.2,0.6,0.9,1]}
{"type":"NodePath","value":"Parent/Child"}
{"type":"Basis","value":[[1,0,0],[0,1,0],[0,0,1]]}
{"type":"Transform3D","basis":{"type":"Basis","value":[[1,0,0],[0,1,0],[0,0,1]]},"origin":{"type":"Vector3","value":[1,2,3]}}
```

Basis vectors are **columns**, not rows. Transform3D origins are translations.
Raw `rotation` properties use radians; `rotation_degrees` and `node.set_transform`
rotation use degrees. JSON numbers must be finite. Singular basis values and
zero transform scales are rejected by the relevant typed transform operation.

Resources are constructed from a fixed class/property allowlist:

```json
{"type":"BoxMesh","properties":{"size":{"type":"Vector3","value":[2,3,4]}}}
{"type":"StandardMaterial3D","properties":{"albedo_color":{"type":"Color","value":[0.8,0.4,0.2,1]},"roughness":0.7}}
{"type":"CapsuleShape3D","properties":{"radius":0.5,"height":2}}
```

Supported constructors: BoxMesh, SphereMesh, CylinderMesh, PlaneMesh,
StandardMaterial3D, BoxShape3D, SphereShape3D, CapsuleShape3D. Existing resource
paths are metadata, not permission to load arbitrary resources. Assignments
replace the node's resource; they do not edit shared external resources in place.
`node.properties` reports the allowlisted properties available on that node.

## Editor-play logs

`game.logs` with `mode: "editor"` reads the debugger log ring kept by the plugin:
params `since` (cursor, optional) and `limit` (1-5000, default 1000). The result has
`entries` (each with `seq`, `run`, `session`, `kind` of `log`/`run_started`/`run_stopped`,
`level`, `message`, `time` and for engine errors/warnings `file`, `line`, `function`,
`code`), `next` (cursor for the following call), `missed` (entries evicted before
being read), `dropped` (entries the game discarded under backpressure), `running`,
`run` and `epoch`. Sequence numbers increase for one plugin session; a changed `epoch`
means the cursor space restarted. `file`/`line` are the innermost GDScript frame when
available, with the engine's C++ origin in `native_file`/`native_line`.

## Runtime inspection (editor play)

`runtime.tree` (`path`, `max_nodes` 1-5000), `runtime.inspect`, `runtime.properties`,
`runtime.get_property` and `runtime.set_property` forward a request id and params
to the played game over Godot's debugger channel (`godotbridge:<command>`) and
return the game's reply, or `GAME_NOT_RUNNING` / `TIMEOUT` (five seconds). Paths are
relative to the running scene (`.` is its root) under the node-path rules above;
values use the typed encoding and the same allowlist and type checks as `node.*`.
Edits live only in the running game. `debug.status` returns `running`, `breaked`,
`sessions` and `dap_port` (the editor setting `network/debug_adapter/remote_port`)
from the editor debugger sessions.

## Error code vocabulary

EDITOR_DISCONNECTED, AUTHENTICATION_FAILED, PROTOCOL_MISMATCH, INVALID_ARGUMENT,
INVALID_NODE_PATH, NODE_NOT_FOUND, SCENE_NOT_FOUND, SCENE_NOT_OPEN,
RESOURCE_NOT_FOUND, UNSUPPORTED_NODE_TYPE, UNSUPPORTED_PROPERTY,
UNSUPPORTED_OPERATION, READ_ONLY_RESOURCE, FILE_ACCESS_DENIED, PROJECT_NOT_FOUND,
GODOT_NOT_FOUND, TIMEOUT, EDITOR_BUSY, TRANSACTION_FAILED, CAPTURE_UNAVAILABLE,
GAME_NOT_RUNNING, INTERNAL_ERROR. Some codes are reserved for future operations. Error details may
contain bounded worker diagnostics; credentials are never included.
